# Client update

Cicero Web Studio (CWS) clients are busy local business owners. Many speak English as a
second language. This skill turns the internal project status into a message they'll
actually read, and that shows the care behind the monthly plan.

## Source

Read the client's status doc first: `Clients/<Business Name>/00 STATUS.md` in the studio's
Google Drive (the file the `handoff` skill maintains). If you can't reach Drive, ask Tulio
to paste it. Use only what the doc and this conversation say. Never invent progress, numbers
or dates.

If Tulio wants real numbers (calls, Google views, visits) and you have read access to the
source (Google Business Profile, analytics), pull them and say which dates they cover. If
you don't have the numbers, leave them out. Don't estimate.

## Pick the type

- **Progress update** (during setup or build): what's done, what we need from them, what's
  next.
- **Monthly note** (care plan): what we did this month, one result or observation if
  verified, one suggestion, and anything we need.
- **Need something** (blocked): the one thing we need, why it matters, and the easiest way
  to send it.

## Message rules

- Language: the client's language. If the status doc doesn't say, ask Tulio.
- Length: WhatsApp or text 3–5 short lines; email 5–8 short sentences plus up to 3 bullets.
- Start with what got done, then what's needed from them (bold, one ask at a time if
  possible), then the next step.
- Name the work in their words: "tu página de servicios", not "the services route". No
  jargon (SEO, schema, deploy, DNS). Say what it does for them ("para que te encuentren en
  Google Maps").
- Warm and personal, from Tulio. Care, craft, trust. No AI or tech talk.
- No promises about rankings, leads or dates unless the status doc records them as agreed.
- If the client asked for something outside their plan, don't say yes or no in the update.
  Flag it to Tulio as: correction / included revision / likely scope change / unclear.

## Output

1. The message, ready to copy, with an email subject line if it's an email.
2. For Tulio only:
   - What it's based on (status doc date, any data source and its dates).
   - Anything to check before sending (asks, promises, scope flags).
   - Suggested line to add to the status doc's "Done" or "Open questions" after it's sent.

## Hard limits

- Draft only. Tulio sends. Never email, text, WhatsApp or post for him.
- Never include passwords, invoices, card or account numbers in the message.
- Don't save client details into this repository (it is public).
